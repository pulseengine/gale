# v0.6.0-rc — the Research Day cut (freeze 2026-08-03)

A date-driven re-scope of [v0.6.0 "Reach and Rigor"](v0.6.0-breadth-depth.md). Nothing
here is new ambition; it is the existing v0.6.0 scope reordered around a hard external
date, with an explicit boundary around what will *not* be claimed.

## Why this cut exists

A talk proposal went to Wasm Research Day (Princeton, 2026-08-06): *"Change the Tires,
Not the Car: the Component Model as the Integration Step for an OS Written in
WebAssembly."* Separately, the Component Model update to the CG on 2026-08-04/05 will
mention and link this project in its implementation-status section.

Two consequences:

1. **The real freeze is 2026-08-03**, not the 6th — the implementation-status slide is
   written before Research Day, so the headline artifact has to exist before the CG
   meeting, not before our own talk.
2. **The public promise was deliberately kept small.** The submitted abstract claims
   only two concrete things: components that already speak the OS seam, and the same
   set lowered ahead of time to a single native object running on real silicon. Both
   were already true when it was submitted. Everything in MUST below is over-delivery
   against a promise we can already keep — that asymmetry is the point, and it is the
   only acceptable direction for it to run.

## The rule this cut is under

Unchanged from v0.6.0: **scope is committed, claims are not.** Anything that does not
close honestly by the freeze ships with its gap stated, on the talk's own honesty slide.
A slide that outruns the repo is a worse outcome than a shorter talk.

### M1 is assembly, not invention — measured state (2026-07-29)

Five provider crates exist. Four componentize cleanly today:

    log-provider     core 1450 B  ->  COMPONENT 1835 B
    spawn-provider   core 1974 B  ->  COMPONENT 2614 B
    time-provider    core 1663 B  ->  COMPONENT 2518 B
    timer-provider   core 1715 B  ->  COMPONENT 2220 B
    exec-provider    core 4334 B  ->  FAILS: module requires an import interface named `env`

`exec-provider` is the single blocker, and it is a seam defect rather than a design one:
it carries one raw import, `env.poll_task`, and three raw `#[no_mangle]` exports, and it
was never given a WIT world. `interface taskdisp { poll-task: func(id: u32) -> u32; }`
already exists and is exactly that import; `spawn-provider` and `timer-provider` both
*import* `taskdisp`, and nothing exports it. So the composition graph has a hole at its
centre, and closing it is: add an `exec` interface + `exec-provider` world, and move the
crate onto the same `wit_bindgen::generate!` pattern the other four already use.

Order of work: componentize `exec-provider` -> add all five to the gated PROVIDERS list
-> `wac plug` into one composite -> confirm the residual is exactly `gust:hal`.

### What actually happened (updated 2026-07-29)

Both halves of that plan were wrong in instructive ways, so they are recorded rather
than quietly corrected.

**`wac plug` was structurally inapplicable.** The five providers were a flat antichain —
each exported a capability, none consumed another's — so there was no edge to plug, and
every ordering failed with `the socket component had no matching imports`. The composite
was built with `wac compose` instead (#235).

**And the acceptance criterion turned out to be satisfiable without the property it was
meant to guarantee.** The composite exports `gust:os` with residual exactly `gust:hal` +
the app-supplied `taskdisp` — criterion met — while `exec`, `spawn` and `timer` each
`#[path]`-included the same `executor.rs` with its own `static mut TASKS`. Three
schedulers behind one façade; a handle from `spawn.start()` meaningless to
`timer.sleep()`, which is a promise `gust-os.wit` already makes in `timer.sleep`'s own
doc comment. The same shape appeared a second time in the clock: `timer-provider` and
`time-provider` each hardcoded `TIM2_CNT` and read it independently.

Worth stating positively: none of this was visible while everything linked into one
native image. Expressing the OS *as components* made it structurally explicit.
Composition worked as a diagnostic, and that is a better talk than a clean success.

The fix — `spawn` and `timer` importing rather than embedding, a separate
`gust:sched/tasks` package so scheduler mutation stays out of the published world, and
`timer` taking its clock from `gust:os/time` — is in flight for this cut.

## WON'T — stated as gaps, not attempted

- ~~**Drivers across architectures.**~~ **This moved to done on the day it was written.**
  synth's RISC-V backend dropped any function containing an imported call
  (`external call without relocation table`); filed as synth#871 that morning and fixed
  that afternoon in synth 0.52.0, which emits `R_RISCV_CALL_PLT`. Six of eight thin
  drivers now lower completely to RV32 with the seam intact — `drivers/CROSS-ARCH.md`.
  Two functions still decline (synth#882). Still **not executed** on RISC-V silicon, and
  could not be as-is: these carry STM32 register maps. So the honest residual gap is
  narrower than the original entry, not absent — it is now "compiled on both, executed
  on one".
- **On-device hosting of replaceable tenants.** Components run on a host engine and on
  the component host today; hosting on the MCU itself is the next rung, not this one.
- **scry loop-bound inference.** Worst-case sidecars are emitted per function today;
  functions with loops carry `reason=loop` because a sound bound needs a trip count.
  That gap is named in `emit-wcet.sh` and stays named.
