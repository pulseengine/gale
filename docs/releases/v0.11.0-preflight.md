## (i) The two-domain module

The image is the one synth#1622 describes:
- `hm-thin`, `mpu-thin` and `switch-thin` are built with `drivers/build-reloc-cores.sh`;
- then fused with
  `meld fuse hm-thin.comp.wasm mpu-thin.comp.wasm switch-thin.comp.wasm --memory shared --pack-rebase --domain tenant=hm-thin.comp.wasm --domain supervisor=mpu-thin.comp.wasm,switch-thin.comp.wasm --memory-page-size 1`;
- then compiled with
  `synth compile --target cortex-m3 --all-exports --relocatable --native-pointer-abi`.

`--domain` takes an input's name exactly as given. `tenant=hm-thin` is refused:
"names an input that was not given".

Both melds give `(memory 2080 2080 (pagesize 0x1))` and `(memory 5392 5392 (pagesize 0x1))`.
Memory 1 has 13 i64 accesses: `i64.load` ×2, `i64.store` ×8, `i64.load32_u` ×3.

| synth \ fused by | meld 0.66.0 | meld 0.67.0 |
|---|---|---|
| 0.89.0 (control) | exit 1: 4 of 45 skipped (`I64Load32U`/`I64Store … on memory 1 is not lowered in phase 1`), then #1102 refuses (6 retained functions call declined ones) | same |
| **0.90.0 (candidate)** | exit 0, `Compiled 45 functions`, 0 skip or decline lines | exit 0, same object (`sha256:c47f523c…`) |

About the candidate object:
- `__synth_mem_size_0 = 0x820` and `__synth_mem_size_1 = 0x1510`, which equal meld's
  extents.
- `__synth_mem_count = 2`.
- Sizes: text 8390, data 5416, bss 2064.
- The undefined set is exactly the four seams: `ctx-resume ctx-save mpu-write region-swap`.
- `cargo xtask check data-overlap --module <two.fused.wasm>` passes: 6 segments, all
  disjoint.

**Denominator:** 45 exported functions, the count synth reports under `--all-exports`.
The earlier record said 52 of 56, measured on source at 23dd0b4. The source has moved
since then (memory 1 went from 5376 to 5392 B), so the 56 doesn't apply to this tree.

**What this can't see:**
- Whether the object *executes* correctly. Nothing ran it: no wasmtime differential, no
  Renode run, no board.
- How large the image is with the loom pass. loom refuses the module, so this is the
  loom-free object.

## (iii) Renode

Commands:
- `cargo xtask renode-elfs` in each scratch clone. The images link the rebuilt
  iso-core, mpu, switch, dma-own, exec and gustos objects, plus the committed thin
  objects, because the pass-2 thin objects don't link (see ii).
- Then `renode-test <robot> --variable ELF:… --variable REPL:…` for each target in
  `os/gust/renode-test/BUILD.bazel`.

Renode was the local 1.16.1 arm64 build; CI pins 1.15.3.

This run is not evidence under 1.15.3, and it could not be made locally: the 1.15.3
builds are x86_64 only, this workstation has no x86_64 translation layer or container
runtime, and the probe hosts are arm64. The 1.15.3 evidence for (iii) is therefore owed
by the pin PR itself: `gust-renode.yml` runs on every pull request against main, pins
1.15.3 (os/gust/renode-test/MODULE.bazel), and reports the required context "gust
dissolved on Renode". The pin PR must not merge unless that job passes on the rebuilt
fixtures, and its body must say so.
