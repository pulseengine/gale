The release, as distinct from the two planning documents behind it:
[v0.6.0-breadth-depth.md](v0.6.0-breadth-depth.md) is the original scope and
[v0.6.0-research-day-cut.md](v0.6.0-research-day-cut.md) is the date-driven re-scope.
This file is what actually ships, what gates it, and what ships *with its gap stated*.

## Why there is a release at all, and why before 2026-08-04

The Component Model update to the CG on 2026-08-04/05 will mention and link this
project in its implementation-status section, and Research Day follows on the 6th.

A branch is not an implementation status. A **published, signed, pullable component** is.
`DD-OS-DELIVERY-001` already says gale's consumable cut is a cosign-signed OCI wasm
component exporting `gust:os` — so the release is not packaging around the work, the
release *is* the deliverable that decision describes. Tagging is what turns the artifact
into something a third party can verify without asking us.

That sets the freeze at **2026-08-03**.

## Shipping with the gap stated

The rule from the re-scope holds: scope is committed, claims are not. These ship
*disclosed*, not hidden or quietly dropped.

- **The composite has never been executed.** "One scheduler, one clock" is verified
  structurally — by import routing across the unbundled core modules — and by source
  ownership. Nobody has called `spawn.start()` and observed the handle in `timer.sleep()`
  through this composite. No wasm runtime, no dissolve of the composite, no hardware.
  This is the single largest gap in the release and the first thing v0.7.0 should close.
- **The composite is not lowered to native.** 20 741 B is a *wasm* number. No `.o`, no
  code size, no SRAM figure, no cycles.
- **RISC-V is compiled, not executed.** Six of eight drivers lower completely to RV32
  with the seam intact; none has been run there, and none meaningfully could be — they
  carry STM32 register maps and there is no RV32 target model. Two functions still
  decline (synth#882).
- **The dissolve remains a trusted build step**, not a verified translation. Unchanged,
  and still the honest centre of the story.
- **`spawn-provider-cm3.o`, `timer-provider-cm3.o`, `os-ts-cm3.o` and `exec-cm3.o` are
  stale** with respect to the new architecture; `exec-cm3.o` additionally has a pending
  `poll_task` -> `poll-task` symbol-contract change. Regenerating them is a reviewable
  change of its own, deliberately not bundled into a re-pin or an architecture fix.

## Explicitly deferred to v0.7.0

- **Execute the composite** — on a host engine first, then dissolved. This turns the
  release's largest gap into evidence.
- On-device hosting of replaceable tenants (the migratable tier).
- witness MC/DC and scry loop-bound inference pointed at the OS itself.
- An RV32 target model, which is what a faithful RISC-V silicon result actually needs.

## Sequence

evidence, and the whole point of this cut is that a third party can check it without us.
