# v0.11.0 "Behind the Line" (plan)

Signed component, unprivileged on silicon. Planned 2026-11-19 against `origin/main` at
`e85b7620`; the latest tag is `v0.10.0`. Nothing in this plan is implemented. Every
figure below came from a command run against that commit, and the last section lists
each command with its denominator and what it cannot see. Figures taken from a tracker
or from an artifact's text are marked "recorded, not re-measured".

## Thesis

rivet scopes 10 artifacts to v0.11.0, all `proposed` (`rivet release status v0.11.0`:
10 of 10 not release-ready). Together they make one claim: a tenant runs unprivileged
behind a memory boundary the supervisor programs, and the memory-protection primitive
ships with its embedder obligation named. This plan keeps that scope and ties it to the
North Star sentence, "signed code running on a microcontroller, with evidence an
assessor can re-check".

**T1, the single item that gates the thesis:** one image, built in the run from one
signed component pinned by digest, runs its tenant unprivileged on a physical board;
both escapes fault, and both control arms show the escape landing. If T1 is not green,
there is no v0.11.0 tag, whatever else is green.

This is a demonstrator release: one tenant, the tenant-to-supervisor direction only, on
at most 2 SoCs. It makes no production claim, no multi-tenant claim and no
certification claim.

**Time box: the 2026.12 varve layer.** A bet that is not green on the day that layer is
published is dropped from v0.11.0, or the release is re-planned that day.

## Bet 1: one tenant runs unprivileged behind a programmed boundary, on silicon

- **Objective: O1, as a precondition, not an indicator movement.** O1's indicator is
  jess's ladder plus synth's reach, execution match and WCET. This bet moves none of
  them. It supplies a gale-local row beneath jess's first rung: a dissolved component
  that runs under gust, on a board, on the unprivileged side of a boundary. O1 stays
  `unmeasured`. Proposing that row as an addition to O1's indicator would be a North
  Star change and is not assumed here.
- **gale-local proxy:** targets with an unprivileged-tenant four-arm result, from 0 to
  2 (WB55RG and G474RE). O1's guard applies: WL55JC1 is a stretch row, and if it is not
  run it is published as a failure, not omitted.
- **Acceptance.** Each item can fail; all are red today because the bin does not exist.
  1. **Four arms, one image family, per board.** `cargo xtask silicon run <board>
     gust_tenant_unpriv`:
     - *protected arm:* tenant at `CONTROL.nPRIV=1`, regions programmed. Both escapes
       must fault: a write to `MPU_CTRL` (tests the privilege bit) and a write to a
       supervisor-private RAM address (tests the programmed region).
     - *control A (`no-drop-priv`):* tenant privileged, regions programmed. Both writes
       must land.
     - *control B (`no-regions`):* tenant unprivileged, private region not programmed.
       The `MPU_CTRL` write must still fault and the private-RAM write must land.
       Without this arm, an unprogrammed MPU passes the protected arm's first escape.
     - PASS, per escape, means: the fault handler ran with the expected fault address,
       `CONTROL` read back as 1, and privileged code read the target value back
       unchanged. A fault with a changed value is FAIL.
  2. **The old probe stays as a recorded control.** `gust_iso_unpriv_probe` is kept,
     not deleted, in the change that lands the seam. It is renamed in the matrix as
     the privileged-escape control with its expected verdict stated, so the
     difference between the two is observed in one matrix run.
  3. **A leg closes only on evidence.** `cargo xtask check criticality-axis` changes
     so that a leg may leave the known-open ledger only if it links a verification
     artifact whose named matrix row is PASS in the published JSON at the same commit.
     Planted bad input in its self-test: a leg marked closed with no such row fails.
     Only then may `FFI-WB55-001`'s spatial leg close, and only for tenant to
     supervisor on the STM32WB55. Today the gate prints 3 open legs.
  4. **The shipped MPU artifact names its obligation.** A gate fails if the release
     manifest entry for the MPU module does not name `mpu-write` as the embedder's
     obligation; this is `REQ-OS-MPUSHIP-001`'s own kill criterion, made mechanical.
     Planted bad input: a manifest without the field.
- **Kill criteria:**
  - **1(a)** Any escape lands in the protected arm on any board and is not fixed by
    the 2026.12 layer: bet failed, no tag.
  - **1(b)** By **2026-11-28**, a link-map check (no board) shows the two-domain image
    does not fit the G474's 96 KiB: the claim narrows to WB55, the G474 row is
    published as a failure with that reason, and the tag may still be cut on WB55
    alone, with the release title and notes saying "one SoC". If it does not fit the
    WB55 either, the bet failed.
  - **1(c)** The seam adds more than 1 trusted atom beyond `mpu-write`. A trusted atom
    is counted mechanically: an entry in the undefined-symbol set of the fused
    supervisor object that native privileged code supplies, plus each hand-written
    privileged function (assembly or `unsafe` Rust) on the supervisor-call path.
    Checked at design review, before code, by **2026-12-03**. If exceeded, stop and
    re-plan the seam.
  - **1(d)** Capacity: if T1 has not been attempted on a board by **2026-12-10**, the
    owner is told that day and the release is re-planned.
- **Dependencies:**

  | dependency | state, 2026-11-19 | owner | fallback |
  |---|---|---|---|
  | synth 0.89.1 or later in a layer | 0.89.1 and 0.90.0 released; not pinned | varve and covalent maintainers | none; bet 1 does not start without it |
  | loom accepts `(pagesize 1)` (loom#457) | open | loom maintainers | dissolve this one image without the loom pass and report the size measured both ways |
  | meld `--domain`, `--memory-page-size 1` | in pinned 0.66.0 | n/a | n/a |
  | synth#1145 umbrella | open | synth maintainers | not blocking if item 0 check 1 passes |
  | jess as consumer (gale#348) | waiting | jess | none needed; informed at tag |

- **Builds on:** `REQ-OS-UNPRIV-001`, `REQ-OS-MPU-001`, `REQ-OS-MPUSHIP-001`,
  `REQ-OS-CRITICALITY-001`, `CA-WB55-001`, `CA-WB55-002`, `FFI-WB55-001`,
  `FFI-WB55-002`, `SAC-GUST-SUP-001`, `SAC-GUST-TENANT-001` (v0.11.0, proposed);
  `REQ-OS-PRIVREGION-001`, `VER-OS-PRIVREGION-001` (verified); gale#408, gale#437.
- **Size:** L. **Main risk:** the supervisor-call path is new privileged code that no
  existing proof covers. Verus and Kani cover the region table and the switch state
  machine. That the hardware honours the permission bits is an architectural
  assumption, discharged per board by the four arms and by nothing else.
- **Not shown:** isolation between two tenants (`REQ-OS-MULTITENANT-001`, v0.13.0);
  temporal or information isolation; anything on the F100 (no MPU) or the G031K8
  (ARMv6-M PMSA cannot distinguish the modes).

## Bet 2: the flashed image comes from a signed component by digest, and the matrix is published

- **Objective: O1, as a precondition and an application of its guard.** It moves
  neither O2's indicator (releases carrying the bundle) nor O3's (required proof checks
  with a ledger) and is not labelled with them.
- **gale-local proxies:**
  - silicon rows whose flashed image is built in the run from a signature-verified
    component: from 0 to 1 required (T1) plus 4 targeted (the fused `gust:os`
    composite probe on F100, WL55JC1, WB55RG and G474RE);
  - the matrix as a published, guard-compliant file: from not published to published.

  How this feeds O1: an O1 indicator script can read "execution on the shipped ELF, per
  target" from that file, because each row binds a commit, a component digest and the
  hash of the image that was flashed.
- **Baseline, shape only.** 93 rows over 6 boards and 21 bins; 34 are NOT-YET by
  declaration and 59 are runnable. **59 is a ceiling, not a result:** in the planning
  pass all 59 were REFUSED (no probe host configured) and 0 rows were observed to pass.
  The 34 NOT-YET rows by reason: 12 cite synth#1301; 8 are the 1.1 MiB span of
  `fused.o` (bins `gust_stack`, `gust_fused`); 8 are excluded by hardware (5 no MPU on
  the F100, 2 ARMv6-M PMSA, 1 SRAM size); 3 use STM32F1 peripheral addresses on other
  parts; 2 are two-tenant memory size; 1 is the ESP32-C3. The provenance target bin
  `gust_osfused_probe` is not one of the 8 `fused.o` rows.
- **Acceptance:**
  1. **T1.** `cargo xtask silicon run wb55rg gust_tenant_unpriv --component
     <ref>@sha256:<digest>` pulls the published component, verifies its signature
     against the repository's workflow identity, dissolves and links it with the frozen
     pin, flashes, and returns PASS on the protected arm, with controls A and B built
     from the same digest. The row declares its component, so a run without
     `--component` is REFUSED. Red today: `tools/xtask/src/silicon.rs` has 0 matches for
     cosign, OCI, digest or signature.
  2. **Pre-release signing path.** The tag is gated on a silicon run of a component
     signed by a workflow identity, so the digest must exist before the tag. The
     publish workflow already accepts a manual run with a version
     (`workflow_dispatch`): a release-candidate version is published and signed that
     way, T1 runs on its digest, and a release-time check fails unless the tagged
     release republishes the same digest.
  3. **Refusal controls** in the xtask self-test, run in CI: one byte changed is
     REFUSED before flashing; a valid signature from another identity is REFUSED; a
     declared row with no component is REFUSED. There is no fallback to a committed
     object.
  4. **Dissolved versus committed.** A gate compares each object dissolved from the
     published component with its committed counterpart: byte-equal, or the pair is on
     a ledger naming the single differing input. The ledger fails in both directions.
     Kill 2(a) is decided by this gate's output.
  5. **Published file with a freshness rule.** `silicon-matrix.json` is published with
     a check that fails if a declared row is missing, if any row's commit is not the
     commit being tagged, if a row lacks the flashed image's hash, or if a PASS row
     lacks the OK-line evidence. NOT-YET and REFUSED rows count as failures in the
     summary.
  6. **No bench topology in the file.** A check with a planted bad row fails if any
     field carries a host name, address, probe serial or USB port path.
  7. **Pass threshold for the tag.** T1 PASS; and no row that an earlier record shows
     as PASS reports FAIL or REFUSED (each such row blocks the tag until fixed, or until
     the notes name it as a regression the owner accepted); and at least **53 of 93**
     rows PASS. 53 is the count of passing runs recorded in `REQ-OS-INTEGRATION-001`'s
     text (recorded, not re-measured). If the first full re-run shows that figure was
     wrong, the floor is reset once, in writing, before the tag.
- **Stretch, not acceptance:** a second witness for one row from the logic analyzer,
  judged by `cargo xtask la-check` (lane `l6-la-reference`, not on main).
- **Kill criteria:**
  - **2(a)** By the 2026.12 layer, gate 4 shows a difference that cannot be put on the
    ledger with one named input: bet failed for that object; if the object is in T1's
    image, no tag.
  - **2(b)** By **2026-12-03**, the published component cannot be dissolved for WB55
    without edits that are not in the component: the bet is re-scoped to "signed source
    of one board's image", and the notes say the many-targets claim is false as stated.
  - **2(c)** At the 2026.12 layer the threshold in item 7 is not met: no tag. The lower
    number is published either way.
- **Dependencies:**

  | dependency | state | owner | fallback |
  |---|---|---|---|
  | signature verification tool (wsc 0.12.0 in the layer; cosign in CI) | present | sigil maintainers | cosign alone, as the publish workflow uses today |
  | rustc pin (gale#454) | open, needs a decision | gale | ledger the difference under gate 4 with rustc named |
  | item 0, frozen pin | not started | gale | none |
  | bench access (boards, a probe host) | shared with bet 1 | gale | the serial order above |
  | lane `l6-la-reference` | unmerged | gale | stretch only |

- **Builds on:** `DD-OS-DELIVERY-001`, `REQ-OS-DELIVERY-001`, `VER-OS-DELIVERY-001`
  (verified); `VER-SILICON-MATRIX-001` (verified; 11 of its PASS rows were taken under
  the older bare-exit-0 rule and never re-run); PR #529, gale#438, gale#506, gale#386.
- **Size:** L. **Main risk:** reproducibility of the dissolve, for reasons unrelated to

- **Not shown:** nothing on the target checks a signature; verification happens on the

## The ratchet policy

O3's guard says ledger entries may only shrink. Bet 1 adds trusted code and new Kani
harnesses, so a shrink-only gate from day one would turn red on bet 1's own work. The
policy:

1. Until the baseline is set, the ledger gate runs as an **equality ledger**: any
   change in any class, up or down, fails unless the same change updates the ledger
   with the artifact ID that justifies it.
2. The **baseline is set once, at the v0.11.0 tag commit**, after bet 1's growth has
   landed, and is recorded with the count of growth admitted during the release. Bet 1
   may admit at most 1 trusted atom (kill 1(c)).
3. From the baseline on, the gate is **shrink-only**. Growth is red and needs an
   owner-approved ledger entry; there is no other path.

This is the planner's proposal and the owner can overrule it. It needs no decision
before work starts, because step 1 is safe either way.
