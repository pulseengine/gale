# v0.9.0 — "On Metal"

gale's OS layer has been demonstrated on emulators for most of its life. qemu and
Renode are fast, scriptable and honest about what they model — and both of them read
unmapped memory as zero, which is how a dissolved object that dereferences an address
no embedder ever backed passed its gate for months. This release moves the OS layer
onto real parts, with a runner whose verdict comes from the firmware rather than from
an exit code, and reports what the boards said.

## The falsification statement

**Claim under test:** gust's OS layer — the verified executor, the `gust:os` capability
nodes and their fused composite, the health monitor, the timer, the dissolved drivers and
the MPU region programmer — runs on real silicon, not only on emulators, and the
componentized drivers reproduce their pre-change hardware baselines.

**It survived, and it cost three corrections to get there.** Running the images on parts
refuted three things the emulator gates had been reporting as green:

1. `gust_os_probe` passed on qemu only because unmapped memory reads as zero. On silicon
   it is a precise BusFault at `0x0010_0008` — the dissolved `os-time` node reads and
   writes wasm data through a register no embedder sets, and its build script calls that
   object "0 SRAM" (gale#398).
2. The same class in `breadth-cm3.o` (40 accesses): BusFault at `0x0010_000D` on the F100.
3. Three committed bench scripts reported success they did not have — an exit masked to 0
   by bash 3.2, an unclaimed attach on a shared host, and a wrong-board attach under a
   correct claim (gale#397).

## What shipped

**A silicon runner whose verdict is the firmware's.** `cargo xtask silicon
{list|run|matrix}`: builds a bin from the board's measured target model, flashes it under
a `with-device` claim taken on the host that owns the probe, and returns PASS only on the
firmware's own `OK` line or its semihosting exit 0 — FAIL on its `FAIL` line, and REFUSED
(exit 3, never a pass) on anything else, including a deadline or a busy probe. Negative
control: an image built to fail (`grant-hole`) reports FAIL, and openocd exits non-zero.

**Five boards, from three measured target models.** NUCLEO-WL55JC1, NUCLEO-WB55RG and
NUCLEO-G031K8 join the STM32F100 and NUCLEO-G474RE. Every value in the new `.aadl` models
was read from the part: CPUID, DBGMCU, `MPU_TYPE`, flash size, SRAM bounded by a fault one
byte past the end, and `RCC_CSR`'s RMVF/IWDGRSTF exercised rather than assumed.

The G031K8 is gale's first ARMv6-M silicon. It runs everything that is native Rust; no
dissolved object runs there until synth has an ARMv6-M profile (synth#1301, v0.69
candidate).

**REQ-DRV-SILICON-001 closed by measurement.** The componentized `wdg-thin` and `adc-thin`
re-observed against their July baselines: IWDGRSTF set on F100 and G474, Vrefint 1644 raw
(baseline 1646) inside the firmware's own band. The `RCC_CSR` bits that differ are the
harness — decoded in `silicon/RESULTS-componentized-rerun.md` — and the bit the two-boot
proof is about is identical in every run. (`VER-DRV-SILICON-001`)

**REQ-OS-MPU-001's kill-criterion on silicon.** The synth#1145 two-tenant pair, previously
Renode-only, on the WB55: with regions programmed through the Verus+Kani-verified
`switch_to_partition`, the unprivileged tenant A's write at tenant B's base **faults**;
with `no-regions`, the same escape **lands in B** (`b_load(0)`=0xbaddbadd). The control is
what makes it evidence: a single green would prove the platform, not the programming.

**gale's Zephyr kernel replacements reach upstream parity.** The coverage gate had run
zero kernel tests since March; once it ran, the first honest comparison showed **38**
upstream-passing suites that gale broke. Now **0**: 146 of 147 pass on both sides, and the
single failure fails upstream too. Causes were ordinary and specific — a Kconfig
dependency, a dropped weak symbol, v4.4 tracing signatures, a scalable-wait-queue
assumption, a no-multithreading link reference, an orphan `.note.GNU-stack` — plus one
that was not ordinary: **all 43 cargo invocations built a Kconfig-dependent library into
one shared directory**, so parallel twister configurations overwrote each other's.

**The Zephyr fork is pinned by revision.** All 15 `west init` sites cloned a branch, so a
run's Zephyr was whatever that branch held and no gale commit recorded it. A gate keeps the
pin reachable, with its own negative control.

## What this release does NOT claim

- **Not a multi-tenant OS.** REQ-OS-UNPRIV-001 is open: gust tenant code still runs
  privileged, and `gust_iso_unpriv_probe` is green *because* that gap is open. The
  two-tenant result is a demonstrator on one part, with hand-written trampolines and a
  report window the tenant can write.
- **REQ-OS-MPUSHIP-001 is deferred to v0.10.0**, by its own sequencing clause: shipping the
  MPU primitive while it is fault-containment-only invites the reading its manifest exists
  to prevent.
- **`gust_stack` and `gust_fused` run on no board.** `fused.o` addresses data 1.1 MiB apart
  through one base register — more RAM than any board here has (gale#398).
- **Two tenants fit only the WB55 today**, and that is toolchain, not RAM: packing and
  per-tenant isolation are mutually exclusive in the current chain, and synth sizes each
  memory by its declared 64 KiB page (synth#1315 — custom page sizes are accepted and
  silently ignored).
- **Physical bench, not CI.** These runs need boards; CI has none. `cargo xtask silicon
  matrix` re-runs them on demand.
- **gpio, timer, spi and uart remain emulation-gated on their own axis.** `gust_breadth`
  exercises all four against real F100 registers, which is a different oracle from the
  per-driver baseline comparison.
