# gale v0.6.0 — "Reach and Rigor"

The consumable cut is now **one signed wasm component that exports the whole `gust:os`
world**, and the same driver sources lower to two instruction sets.

Published to `ghcr.io/pulseengine/gale-nano` and wasm.directory, cosign-signed
(keyless OIDC), alongside the individual `gust:os` provider components.

## The OS ships as one component

`gale-nano` is a single WebAssembly component:

```wit
world root {
  import gust:os/taskdisp@0.1.0;   // the app supplies its task poll
  import gust:hal/mmio@0.1.0;      // the entire hardware seam

  export gust:os/time@0.1.0;   export gust:os/log@0.1.0;
  export gust:os/spawn@0.1.0;  export gust:os/exec@0.1.0;
  export gust:os/timer@0.1.0;
}
```

Anything downstream that imports `gust:os` pulls this component and fuses it for its
own target. The residual is exactly the two-function MMIO seam plus the app's task
poll — nothing else crosses.

The internal scheduler seam (`gust:sched`) is **sealed inside the composite**. It is a
separate WIT package on purpose: a tenant importing the published world cannot reach
`set-deadline` and mutate scheduling state.

## One scheduler, one clock

Composing the OS as components exposed something native linking had hidden: `exec`,
`spawn` and `timer` each embedded their own copy of the executor, and `timer` and
`time` each read the clock register independently. Three schedulers and two clocks
behind one façade — while the WIT already promised that `timer.sleep` takes "the handle
the app holds from `spawn.start`".

`spawn` and `timer` now **import** rather than embed. `spawn` holds no state at all;
its handle *is* the executor's, so the interface's promise is literally true. `timer`
takes its clock from `gust:os/time` and no longer touches `gust:hal`.

Gated: exactly one component instance owns the scheduler, checked by import routing
across the unbundled core modules. Both that gate and the residual-import gate are
negative-tested — a gate nobody has watched fail is not evidence.

## One wasm, two instruction sets

Six of eight thin-seam drivers now lower **completely** to both ARM Cortex-M and
RISC-V RV32 from the same wasm, with the same defined-function count and the same seam
width on each. Deterministic.

The gate is the *undefined-symbol count*, not size. Before this, the RISC-V backend
silently dropped functions containing imported calls, producing a **smaller** object
with zero undefined symbols — smaller and hollow. On this pipeline, a suspiciously
small object is what the failure looks like.

## Smaller everywhere

Re-pinned to synth 0.52.0. Every thin driver shrank or held, none regressed:

    wdg 648->638   gpio 534->502   i2c 974->954   timer 212->204
    adc 740->736   dac 678->642    pwm 706->694   uart 254 (unchanged)

−122 B across the suite, symbol shapes byte-identical, six qemu content gates green,
and the watchdog re-validated on **both** physical dies — STM32G474 (Cortex-M4) and
STM32F100 (Cortex-M3), each reaching `IWDGRSTF=1`.

## What this release does NOT claim

- **The composite has never been executed.** "One scheduler, one clock" is verified
  *structurally* — by import routing and source ownership. Nobody has called
  `spawn.start()` and observed the handle in `timer.sleep()` through this component.
  No wasm runtime, no dissolve of the composite, no hardware. This is the largest gap
  in the release and the first thing v0.7.0 closes.
- **The composite is not lowered to native.** Its 20 741 bytes are a *wasm* figure and
  imply nothing about code size, SRAM or cycles.
- **RISC-V is compiled, not executed**, and could not meaningfully be as-is: these
  drivers carry STM32 register maps, and there is no RV32 target model yet. Two
  functions still decline (synth#882). Import-free logic already has real ESP32-C3
  silicon numbers — that is execution evidence and this is lowering evidence; they are
  different claims.
- **The dissolve remains a trusted build step, not a verified translation.** Kani
  proves source-level state machines; nothing carries those proofs across the lowering.
  Unchanged, and still the honest centre of the story.
- **Several committed objects are stale** with respect to the new architecture
  (`spawn-provider-cm3.o`, `timer-provider-cm3.o`, `os-ts-cm3.o`, `exec-cm3.o`);
  `exec-cm3.o` additionally has a pending `poll_task` -> `poll-task` symbol-contract
  change. Regenerating them is a reviewable change of its own.

## Verify it yourself

    wkg oci pull ghcr.io/pulseengine/gale-nano:0.6.0 -o gale-nano.wasm
    cosign verify ghcr.io/pulseengine/gale-nano:0.6.0 \
      --certificate-identity-regexp 'https://github.com/pulseengine/gale/.*' \
      --certificate-oidc-issuer https://token.actions.githubusercontent.com
    wasm-tools component wit gale-nano.wasm

The last command should show exactly the world above. If the residual imports are
anything other than `gust:hal/mmio` and `gust:os/taskdisp`, the delivery invariant has
been violated and we would want to know.
