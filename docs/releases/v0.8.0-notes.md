# v0.8.0 — "Prove It"

The project has said "tri-track verified — Verus + Rocq + Kani" for a long time.
Two of those three were real. `REQ-OS-TRITRACK-001` says so in its own words: *"the
Rocq track is stubbed."* This release makes the claim demonstrated for one theorem
that matters, and ships the tickless timer whose proofs sit on the other two tracks.

## The falsification statement

**Claim under test:** a load-bearing theorem already proven in Verus and Kani can be
independently discharged in Rocq, over the same source — so "tri-track" names three
tracks that all carry weight, not two that do and one that is aspirational.

**It survived.** `no_lost_wakeups` in `proofs/executor_proofs.v` closes with `Qed.`,
as do its supporting lemma `step_no_lost_wakeup` and the end-to-end corollary
`delivered_wake_survives`. The theorem is load-bearing by the requirement's own test:
it is the executor's no-lost-wakeups property (`REQ-OS-EXEC-001`), not a lemma chosen
for ease of proof.

## What shipped

**T1 — one load-bearing theorem on all three tracks.** For any finite interleaving of
`wake`/`consume`/`pick_next`, once ready bit *i* is set it stays set unless the trace
contains a `consume` of *i* itself. Proven in Rocq against the same executor the Verus
and Kani proofs target. (`REQ-/VER-OS-TRITRACK-001`)

**Tickless component sleep.** `gust:os/timer` — `sleep(handle, ticks)` / `slept(handle)`
— with `set_deadline` + `slept_status` in the verified core:

    Verus   1162 verified / 0 errors   (+2 obligations vs the 1160 baseline)
    Kani    set_deadline_sets_only_h: SUCCESSFUL, 0 of 48 failed
    provider  timer-provider -> 1783 B cortex-m3 relocatable
    seam      undefined = EXACTLY { read32 }        -- a 1-atom TCB

No existing executor function, lemma, or invariant was modified; no `assume`,
`admit`, or `external_body` was introduced. (`REQ-/VER-OS-TIMER-001`)

**The demonstrator refuses to be vacuous.** `gust_timer_probe` drives the real `Tasks`
executor on qemu and reads live state back — no shadow bookkeeping. `expire(deadline-1)`
is a no-op (no premature wake, no spin); `expire(deadline)` readies the task and flips
`slept_status`. Non-vacuity is checked *both* ways: an out-of-range handle reports the
`0xFFFF_FFFF` sentinel, and a freshly-admitted task's `u64::MAX` default deadline reports
pending — so the 0/1/invalid outcomes are distinct reachable branches, not accidents.

## What this release does NOT claim

**"Tri-track" now means one theorem, not the corpus.** The Rocq corpus is
10 files fully discharged, **3 files entirely admitted — 74 theorems stated with zero
`Qed`** (`poll_proofs.v` 22, `sched_proofs.v` 23, `thread_lifecycle_proofs.v` 29), and
one empty file (`heap_proofs.v`, 0 bytes) that is nonetheless a named CI target. `coqc`
succeeds on an admitted proof, so the "Rocq Proofs (14 files)" job was green either way
and could not distinguish stated from proven. That is now gated and ledgered
(`proof-completeness`), which pins the state rather than hiding it. `REQ-OS-TRITRACK-001`
gates every *future* claim that says "tri-track verified" — this release earns that
phrase for `no_lost_wakeups` and for nothing else yet.

**The timer is v1 and single-partition.** `timer-provider`'s `Tasks` table is a separate
instance from `spawn-provider`'s; one table shared across providers in a composed node is
a follow-on. `ticks` is `u32` (bound `ticks < 2^31`), narrowed from the specified `u64`
to work around synth's ARM backend loud-declining a `u64` parameter in a frame-backing
function that also makes a call — filed upstream as synth#837. A wider-range sleep is a
follow-on.

**qemu, not silicon.** The demonstrator is a logic proof on lm3s6965evb. The sleeper is
polled; there is no `.await`. And the Rocq track does not cover the timer feature —
Verus + Kani only, per the tri-track intersection discipline.

## Kill-criteria, unchanged and not triggered

- A Verus or Kani harness fails.
- A due timer is not readied by `expire`.
- The demonstrator re-polls the sleeper before its deadline (spin, not tickless).
- The Rocq proof fails to discharge, or the chosen theorem is found not to be
  load-bearing — removing it would not invalidate an existing claim.
