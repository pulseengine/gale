# v0.7.0 — "Run It, Then Measure It" (plan)

v0.6.0 shipped an OS that composes into one signed component and **has never been run as
one**. Every claim in it is structural: one scheduler and one clock are verified by import
routing and source ownership, not by observing a handle survive a call. The 20 741 bytes
are a wasm figure that implies nothing about code size, SRAM or cycles.

v0.7.0 turns structural claims into observed ones, or finds out they were wrong — and then
measures what it just built.

## The thesis, stated so it can fail

**Claim under test:** the fused `gale-nano` component behaves as one OS — a handle from
`spawn.start()` is valid in `timer.sleep()` and in `exec.state()`, and there is a single
clock behind `time.now()` and the timer's deadlines.

**This is a falsification target, not a demo.** We asserted it from import routing. If
running it refutes the claim, that is the most valuable result this release can produce
and it ships as the headline, exactly as the triplication finding did in v0.6.0.

## Scope: depth now, breadth in v0.7.1

This release was re-scoped on 2026-08-05. Two committed artifacts disagreed about what
v0.7.0 was: this plan said depth-on-one-claim, while the rivet scope typed in #244 added a
third target family, ARINC component tenants, and driver componentization. Both cannot
govern, so the release was **split**:

- **v0.7.0 — depth.** Execute the composite (E1), dissolve it (E2), and the timing triad
  that E2 unblocks (T2/T3/T4).
- **v0.7.1 — breadth.** `REQ-OS-TARGET-RV32-001`, `REQ-OS-PARTITION-TENANT-001`,
  `REQ-DRV-COMPONENT-001` and their verification artifacts, re-pointed there.

The timing triad was **carried in from v0.6.0**, not invented here. It was deliberately
deferred at that release but never re-pointed, so a shipped tag kept querying as unclosed
and six real work items were invisible to any plan. They now sit where the work is.

## Why the triad belongs with the dissolve

This is the reason depth and timing land in the same release rather than separate ones:

    E1  execute the composite ─────► one scheduler / one clock become OBSERVED
         │
    E2  dissolve the composite ────► the first native object for the whole OS exists
         │                            │
         │                            ├──► T2  object-code verification has an object
         │                            └──► T4  per-function WCET has something to bound
         │                                       │
         └────────────────────────────────────► T3  schedulability consumes T4's numbers

T2 has nothing to verify and T4 has nothing to bound until E2 produces an object. Planning
them apart would have scheduled the consumers before the producer.

## The ladder

| # | rung | what it converts | new evidence | artifact |
|---|---|---|---|---|
| E1 | Run the composite on a **host engine** | "one scheduler" structural → observed | a handle crossing `spawn` → `timer` → `exec` | `REQ-OS-COMPOSITE-EXEC-001` |
| E2 | **Dissolve** the composite (fuse + optimise + lower) | the wasm figure into a native one | first real `.text`/`.bss` for the whole OS | `REQ-OS-COMPOSITE-DISSOLVE-001` |
| T4 | Sound per-function **static WCET** | DWT high-water marks into bounds | WCET sidecars without `reason=loop` gaps | `REQ-OS-WCET-001` *(implemented)* |
| T2 | **Object-code verification** of the trusted surface | source proofs into object-level ones | zero-coverage-gap RULE/BIN verification | `REQ-OS-OBJVERIFY-001` |
| T3 | Machine-checked **compositional schedulability** | per-function bounds into a system argument | Lean-verified jittered WCRT recurrence | `REQ-OS-SCHED-001` |

E1 is cheap, fast, and carries the most claim-per-hour: it is the rung that can refute the
thesis. Start there and do not let it slip behind the more impressive-sounding rungs.

E3 (Renode on the composed OS) and E4 (silicon) move to **v0.7.1** with the breadth items —
they are stronger evidence, but they cannot start before E2 and they should not delay a
release that can already ship E1+E2.

## Gates each rung must add

A rung is not done when it runs once. It is done when it cannot silently stop being true:

- **E1** — a test that starts a task, sleeps it via `timer`, and asserts `exec.state()`
  agrees; run in CI on every change to any provider.
- **E2** — the dissolved object's undefined symbols must be exactly the `gust:hal` seam,
  gated like `build-cross-arch.sh` does. **A smaller object with no undefined symbols is
  the failure mode, not the win** — it means the seam was swallowed and the OS is no
  longer swappable.
- **T4** — a WCET sidecar with no `reason=loop` gap on the functions the argument needs.
- **T2** — zero gap rows, not a coverage percentage.
- **T3** — the recurrence machine-checked, not asserted; and its inputs are T4's emitted
  bounds, not hand-entered numbers.

## Carried forward from v0.6.0's stated gaps

These were disclosed at v0.6.0, not dropped. Each closes here or is re-stated with its
reason:

- **Stale objects** — `spawn-provider-cm3.o`, `timer-provider-cm3.o`, `os-ts-cm3.o`,
  `exec-cm3.o`, the last carrying a pending `poll_task` → `poll-task` symbol-contract
  change. E2 forces this anyway.
- **witness MC/DC on the OS** — only meaningful once E1 exists: coverage of something
  executed, not of something composed. The tool is released and has never been pointed
  at this OS.
- **scry loop-bound inference** — closes the `reason=loop` gap in the WCET sidecars, which
  is the one thing standing between per-function bounds and a schedulability argument.
  This is now T4's blocker, explicitly.
- **RV32 target model** — moved to v0.7.1 with the rest of breadth.
- **On-device hosting of replaceable tenants** — moved to v0.7.1
  (`REQ-OS-PARTITION-TENANT-001`).

## Toolchain

Pin stays at **synth 0.52.0**. 0.54.0 was evaluated on 2026-08-05 and its default path is
size-identical to 0.52.0 on every gale input, with a +4 B soundness cost on `gust_kernel`
from the 0.53.0 range-realloc cross-barrier fix. The graph-colouring allocator
(`SYNTH_GRAPH_ALLOC`, −1.0% to −2.6%) ships flag-off and has not been through the Renode
gate, so it is not enabled. See
`benches/gust/drivers/measurements/synth-0.54.0-evaluation.md`.

E2 is the first thing that would justify revisiting this: a whole-OS object is a much
larger optimization surface than the per-driver seams, and the allocator's benefit may
scale with it. Re-measure at E2, do not assume.

## The feedback loop

1. **Run the rung.** Ground every claim in tool output.
2. **Update the ledger.** `docs/releases/*-notes.md` "does NOT claim" sections are the live
   statement of what we know. A rung that succeeds *removes* a line there; a rung that
   fails *rewrites* one. The ledger is never edited to look better.
3. **Route friction the same day** — synth, loom, meld, wac, wasm-tools. Unreported
   friction is friction the next rung re-hits.
4. **Re-derive, don't inherit.** Before a claim reaches a slide or a release note, re-check
   it against the live artifact.

### An input this release actually has

Research Day is 2026-08-06 and the room contains the people best placed to attack this:
compiler-correctness, Wasm semantics, formal methods, and industrial embedded. **Their
questions are v0.7.0 input, not applause.** Capture them the same week, triage them into
this plan, and let the ones that survive scrutiny reorder the ladder above.

The two open asks already carried into that room:

- **translation validation for the dissolve** — the trust moved from a runtime we do not
  ship into a compiler we do not verify, over an alphabet of exactly two effects. E2 makes
  this concrete rather than hypothetical: it produces the object the question is about.
- **what enforces isolation once `meld fuse --memory shared` collapses shared-nothing
  linking into one address space** — raised by a reviewer as the more interesting of the
  two, and unanswered. `REQ-OS-PARTITION-TENANT-001` in v0.7.1 is where it gets answered.

## Not in scope

New drivers, new capabilities and new targets — all now explicitly v0.7.1. Breadth was
v0.6.0's axis; this release is depth on a single claim, plus the measurement that only
becomes possible once that claim is tested.
