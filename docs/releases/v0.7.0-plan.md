# v0.7.0 — "All the way down, and three times over" (plan)

Supersedes the first v0.7.0 sketch ("Run It"), which scoped depth on a single claim. That
was too narrow now that v0.6.0 has actually delivered: the OS ships as one signed,
externally-verified component, so the interesting question is no longer *does the
composite hold together* but **how far down does the component model go, and does it hold
on more than one chip.**

Three axes, all of which v0.6.0 left open in a stated way.

## Where v0.6.0 actually left us

| | state |
|---|---|
| the OS | one signed component, `gust:os` exported, residual exactly `gust:hal/mmio` + app task poll — verified from outside |
| the drivers | **still core modules** with raw `env` mmio imports. Not components. |
| hardware | ARM only: Cortex-M4 (G474) and Cortex-M3 (F100), watchdog on both dies |
| RISC-V | 8/8 drivers *lower* under synth 0.53, none has *run* |
| ARINC-653 outer switch | proofs FULL (Verus 1095/0, Kani 4/4), 3-partition demo on **Renode** |
| execution of the composite | never — one scheduler / one clock remain structural claims |

## A — Component-model drivers, all the way down

Today the composition is typed from the app to the OS and then falls off a cliff: the
drivers underneath are core modules importing `env.mmio_read32`. `gust:hal` already
declares nine interfaces (`mmio`, `irq`, `gpio`, `spi`, `timer`, `dma`, `uart`,
`uart-byte`, `uart-block`) — the types exist and nothing speaks them.

Turning the eight thin drivers into components that import `gust:hal` closes the graph:

    app (component) -> OS (component) -> drivers (components) -> gust:hal -> silicon

The transformation is already proven: `exec-provider` went through exactly this
(`wit_bindgen::generate!` + `wasm-tools component new`) in v0.6.0, including the
consequence that the dissolved object's undefined symbol changes shape
(`mmio_read32` -> the WIT-typed name). Expect that per driver, and gate it.

**What this buys beyond tidiness:** a driver that imports a typed interface can be
composed, substituted and *isolated* by the same machinery as everything else. It is the
precondition for axis C — you cannot put a driver in an ARINC partition as a component if
it is not a component.

**Gate:** every driver componentizes; the composed graph's residual is still exactly the
`gust:hal` mmio seam; no `env` import survives anywhere.

## B — Three hardware targets, one wasm

Two of the three are done for drivers. The third is the honest gap.

- **Cortex-M4** — NUCLEO-G474RE. Watchdog fires, `IWDGRSTF` set, re-validated under the
  shipped pin.
- **Cortex-M3** — STM32F100. Same object, unrebuilt, one unspliced capture.
- **RV32** — ESP32-C3. **Not started as a driver target.** synth 0.53 removed the compiler
  blocker (8/8 lower, counts identical to ARM), so what remains is ours:
  1. an RV32 entry in `targets/` — the target model, not more backend work;
  2. at least one driver written against **real ESP32-C3 registers**. The existing eight
     carry STM32 maps; lowering those for RV32 proves the toolchain crosses and would be
     meaningless to *run*. A GPIO or timer against actual ESP32 registers is the smallest
     honest unit;
  3. then the same arm-and-observe discipline the watchdog got: an effect the hardware
     confirms, captured, with its `n` and splice status stated.

`gust_mix` already has real ESP32-C3 numbers (1.839x native) — that is *execution*
evidence for import-free logic and stays separate from any driver claim.

**This axis also absorbs the old E1.** Running the OS on three chips *is* executing it,
and the structural claims about one scheduler and one clock get tested by the same work.
Do the cheap version first — the composite under a host engine — because it is the rung
that can *refute* those claims, and refutation is the most valuable outcome available.

## C — ARINC-653: components in the partitions, on silicon

The outer switch is not the gap. Its proofs are complete and its properties are strong:
window-end preemption is un-maskable by inner code, and the region-swap is always fully
applied before the entering partition's first instruction. Both Verus/Kani-closed,
`VER-OS-SWITCH-001` verified.

Two things are missing, and they are the interesting ones:

1. **It has only ever run on Renode.** A three-partition major frame on the multi-core
   model is good evidence and is not silicon. Same discipline as the watchdog: put it on a
   real chip and record what the hardware confirms.
2. **The partitions do not host components.** ARINC-653 partitioning of *native code* is
   well-understood. Partitioning **component-based tenants** — where the tenant is a
   signed `gust:os`-importing component, its drivers are components, and the spatial
   isolation is the region-swap the switch already proves ordered — is what this stack is
   actually for, and it depends on axis A.

That gives the two-level structure its real shape: an ARINC-653 preemptive outer switch
(verified) supplying windows to partitions whose inner scheduling is the cooperative
dissolved-async executor — now single-instance after v0.6.0's `gust:sched` work.

**Kill-criterion for C:** a partition observed running past its window on silicon, a
region-swap observed applied after resume, or a component tenant able to reach another
partition's memory or another partition's scheduler state.

## Sequencing, and why

    A (drivers -> components)  ──┬─>  C (components in partitions, then silicon)
                                 │
    B1 (composite on host engine) ─> B2 (RV32 target + ESP32 driver) ─> B3 (all three dies)

A gates C. B1 is cheap, independent, and can refute v0.6.0's structural claims — do it
first regardless of everything else. B2 has the only real unknowns left, so start its
target model early and let it run long.

## The loop (unchanged, because it worked)

1. Run the rung; ground every claim in tool output.
2. Update the "does NOT claim" ledger. A rung that succeeds removes a line; one that fails
   rewrites it. Never edited to look better.
3. Route friction upstream the same day. v0.6.0's record: synth#871 filed and fixed within
   a day; synth#882 filed with two fixtures and fixed in 0.53 — which also caught two bugs
   beyond what was reported, from our inputs.
4. Re-derive before claiming. Three publish failures in v0.6.0 all lived in a tag-gated
   path no PR could reach, so "CI green" never covered it. **A `workflow_dispatch`
   rehearsal before any tag is now standing practice**, and the publish loop names any
   pushed-but-unsigned ref rather than failing silently.
5. Research Day (2026-08-06) feedback is input, not applause — triage it the same week.

## Carried, not dropped

- **synth 0.53 re-pin** (8/8 cross-arch, i2c 954->946 B) — **v0.6.1**, deliberately not
  bundled into a release that has just finished delivering.
- Stale objects: `spawn-provider-cm3.o`, `timer-provider-cm3.o`, `os-ts-cm3.o`,
  `exec-cm3.o` (the last with a pending `poll_task` -> `poll-task` change). Axis A forces
  these anyway.
- witness MC/DC on the OS — meaningful once B1 exists: coverage of something executed.
- scry loop-bound inference — closes the `reason=loop` WCET gap, which is what stands
  between per-function bounds and a schedulability argument for C.
- The two asks taken into Research Day: translation validation for the dissolve, and what
  enforces isolation once `meld fuse --memory shared` collapses shared-nothing linking
  into one address space. **Axis C makes the second one urgent rather than academic** — if
  partitions host components and fusion has flattened their memories, the isolation
  argument has to come from the region-swap, not from the component model.
